> 원문: [Claude Code v2.1.285 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.285)

## 변경사항

- `CLAUDE_CODE_DISABLE_WEB_FETCH` 환경 변수를 추가하여 WebFetch 도구를 비활성화할 수 있도록 함
- `claude --desktop`을 추가하여 현재 디렉터리에서 Claude 데스크톱 앱을 열거나, `--continue` / `--resume <id>`를 사용하여 세션에서 열 수 있도록 함
- `claude plugin configure <plugin>`을 추가하여 플러그인의 옵션을 표시하고 설정되지 않은 옵션을 보거나, `--values-stdin`으로 stdin에서 읽은 새 값을 저장할 수 있도록 함
- `claude plugin install --config`에 `<server>.<key>=<value>`를 추가하여 번들된 `.mcpb` MCP 서버 자체의 설정을 설치 시간에 설정할 수 있고, `/plugin` → Configure을 방문하지 않고도 시작할 수 있도록 함
- `allowedProviders` 관리형 설정을 추가하여 머신이 사용할 수 있는 API 공급자(Anthropic API, 커스텀 엔드포인트, Bedrock, Mantle, Vertex AI, Foundry, AWS 상의 Claude Platform 또는 Cloud 게이트웨이)를 제한할 수 있도록 함
- `CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES` 환경 변수를 추가하여 시간 초과된 비 스트리밍 폴백 요청의 재전송을 제한할 수 있도록 함
- `CLAUDE_CODE_FORK_SUBAGENT=1`을 사용하는 `claude -p`를 수정: 서브에이전트의 자체 Agent 호출이 포그라운드에서 실행되므로 서브에이전트가 자식의 결과를 받도록 함
- SSH를 통한 플러그인 및 마켓플레이스 설치 및 업데이트가 `GIT_SSH` 또는 git 구성의 `core.sshCommand`에서 설정한 ssh 프로그램을 무시하던 문제를 수정
- OS가 관리형 설정 파일 읽기를 거부할 때 Claude Code가 시작을 거부하던 문제를 수정: 이제 경고하고 해당 파일의 정책 없이 시작됨. 기타 읽기 오류 및 파싱 불가능한 파일은 모든 세션을 중지함
- 대화가 압축된 후 다시 시작된 클라우드 세션이 세션이 이미 읽거나 게시한 아티팩트에 대한 다음 업데이트를 거부하던 문제를 수정
- `claude plugin disable` 및 `enable`이 전체 `name@marketplace` id를 사용할 때 설치된 플러그인 자체 대신 다른 대문자 설정 항목을 변경하던 문제를 수정
- Remote Control을 통해 전송된 메시지에 첨부된 파일이 단일 다운로드 실패 후 빠져 있던 문제를 수정: 네트워크 오류, 시간 초과 또는 서버 오류는 이제 최대 2회까지 재시도됨
- 세션 중에 `set_model` 요청(예: Agent SDK의 `setModel`)을 사용하여 모델을 전환할 때 새 모델이 재시작할 때까지 기본 제공 출력 토큰 제한 및 자동 압축 윈도우에 남아 있던 문제를 수정
- 삭제 처리된 로그 및 기록이 `@`을 포함하는 URL 비밀번호 또는 URL이 `@`을 `%40`으로 쓸 때 모두 표시하던 문제를 수정
- 워크트리 및 `/teleport` 페치의 SSH 암호문 및 새 호스트 프롬프트가 터미널을 인수하던 문제를 수정: 이제 이러한 페치는 요청하지 않고 빠르게 실패함
- 세션 중에 추가된 MCP 서버를 비활성화할 때 해당 도구를 사용할 수 있게 남아 있던 SDK 및 `-p` 세션 문제를 수정
- `claude -p --permission-prompt-tool`을 수정: 백그라운드 서브에이전트의 권한 요청이 자동 거부되는 대신 프롬프트 도구로 이동되도록 함
- `claude mcp list` 및 `claude mcp get`, `claude mcp remove`, `login` 및 `logout`의 찾기 못함 오류가 MCP 서버 이름 및 값의 줄바꿈 및 터미널 이스케이프 시퀀스를 인쇄하던 문제를 수정
- 샌드박스 자동 허용이 `=`을 포함하기만 해도 많은 인라인 스크립트(`python3 -c`, `node -e`)의 모든 실행에서 승인을 요청하던 문제를 수정
- 포크 서브에이전트가 세션의 계획 모드 또는 `dontAsk` 모드를 유지하지 않던 문제를 수정: 포크는 이제 부모의 권한 모드에서 실행되고 계획 모드를 종료할 수 없음
- `claude remote-control --help`가 `--[no-]chrome`이 머신의 `/chrome` 설정을 기본값으로 한다고 말하던 문제를 수정: 생성된 세션은 `--chrome`이 전달되지 않는 한 Claude를 Chrome 종료 상태로 유지함
- 자동 모드의 백그라운드 서브에이전트가 각 보고서 후 중복된 두 번째 회신을 표시하던 문제를 수정
- 클라우드 세션 생성 및 `/remote-env` 읽기가 계정의 최신 20개 환경만 읽던 문제를 수정
- Remote Control이 메시지를 Claude가 시작한 시점 대신 메시지가 도착한 직후 읽음으로 표시하고, 터미널이 종료될 때 여전히 큐에 있는 메시지를 잃던 문제를 수정(이제 다음 재개 시 도착함)
- `claude plugin install` 또는 `/plugin`을 사용하여 플러그인을 설치할 때 ID가 `.`, `-`, `@` 또는 (macOS, Windows) 대문자로만 다른 설치된 플러그인의 캐시 또는 데이터 폴더에 들어가던 문제를 수정: 이제 설치가 거부됨
- 훅 및 SDK 권한 콜백이 ExitPlanMode에서 계획이 동일한 응답으로 작성되었을 때 누락되거나 오래된 계획을 보던 문제를 수정
- 클라우드 세션의 첫 번째 응답이 수십 밀리초 늦게 도착하던 문제(2.1.283의 회귀)를 수정
- `ANTHROPIC_AUTH_TOKEN`을 사용하여 Anthropic API에 인증하는 세션이 조직의 정책을 로드하지 않던 문제를 수정
- 워크플로우 스크립트가 나중에 또는 전혀 대기하지 않는 실패한 `agent()`, `parallel()` 또는 `pipeline()` 호출이 처리되지 않은 프로미스 거부로 처리되어 백그라운드 세션을 끝낼 수 있던 문제를 수정
- 훅이 시작한 백그라운드 프로세스(예: `some-daemon &`)가 출력을 계속 열어 있는 동안 동기 훅이 Claude Code를 중단하던 문제를 수정: 훅이 자체 프로세스가 종료된 후 곧 종료됨
- WebFetch가 속도 제한 도메인 안전 확인을 네트워크 또는 엔터프라이즈 정책 차단으로 보고하던 문제를 수정
- 파일 읽기 또는 검색이 많은 턴에서 열려 있을 때 전체 화면 ctrl+o 기록이 잠깐 멈추던 문제를 수정: 기록이 열릴 때 아직 실행 중인 도구 호출이 완료되면 결과를 표시함
- Amazon Bedrock 중간 스트림 `modelTimeoutException` 및 `serviceUnavailableException` 오류가 오류 메시지 대신 raw JSON 본문을 표시하던 문제를 수정
- `/autofix-pr` 및 `/schedule`이 설치 상태가 아직 확인되지 않은 저장소에 Claude GitHub 앱이 설치되지 않았다고 말하던 문제를 수정
- `/artifacts`의 행을 해제(x)할 때 파일을 아티팩트에서 연결 해제하여 동일한 파일을 다시 게시하면 업데이트 대신 새 아티팩트를 생성하던 문제를 수정
- 대화 되감기(Esc Esc) 후 아티팩트 도구가 게시할 때 파일의 최신 콘텐츠를 덮어쓰던 문제(Claude가 되감긴 턴에서만 읽음)를 수정: 이제 Claude가 파일을 다시 읽을 때까지 게시가 거부됨
- 아티팩트 허용 규칙("다시 묻지 않음")이 아티팩트 도구가 작업 디렉터리 외부의 파일을 게시하도록 허용하던 문제를 수정: 파일의 폴더를 `--add-dir`으로 추가하여 규칙이 이를 포함하도록 함
- `/cost` 및 SDK `modelUsage`가 서버가 클라이언트가 예상한 것과 다른 폴백 모델로 거부 응답을 할 때 잘못된 모델 아래에 턴을 보고하던 문제를 수정
- 아티팩트 도구가 페이지를 게시할 때 Claude가 더 이상 먼저 읽음을 다시 읽지 않고 소스 파일을 덮어쓸 수 없도록 수정: Claude의 이전 읽음이 중단되었거나 파일이 변경된 경우
- 자동 모드가 아티팩트 도구 자산 업로드 및 이전에 다른 권한 모드에서 해당 아티팩트를 승인한 경우 다른 사람의 아티팩트 읽기를 위한 분류자를 건너뛰던 문제를 수정
- 프로젝트 폴더를 잠깐 읽을 수 없을 때 `/ultrareview`에서 오해의 소지가 있는 "core.worktree is set" 오류가 발생하던 문제를 수정
- macOS 및 Linux의 `/ultrareview`가 이 워크트리 구성이 `core.longpaths`를 설정한 git 워크트리에서 작업 트리 업로드에 실패하던 문제를 수정
- 아티팩트 도구가 임시 서버 오류를 재시도한 후 게시를 다른 세션과의 충돌로 보고하던 문제(첫 시도가 실제로 성공한 경우)를 수정
- `/ultrareview` 업로드가 `server:8443.key`와 같은 확장명 앞에 콜론이 있는 자격증명 파일에 대한 커밋되지 않은 변경사항을 포함하던 문제를 수정
- 두 세션이 동시에 충돌된 프로세스가 남긴 로그인 새로 고침 잠금을 복구할 때 드물게 인증 실패가 발생하던 문제를 수정
- PowerShell 도구의 권한 확인이 명령 파서 실패(예: 머신 메모리 부족)할 때 거부 및 요청 규칙을 건너뛰고 나중 확인을 위해 해당 실패를 캐시하던 문제를 수정
- macOS 및 Linux의 `/ultrareview` 업로드가 일부 비정상적인 파일 이름에서 느리게 실행되고, 자격증명 파일 확인이 많은 백업 또는 편집기 마크가 있는 파일 또는 폴더 이름을 놓치던 문제를 수정
- 취소가 설정되는 동안 도착할 때 취소된 셸 명령 또는 훅이 여전히 시작되고 끝까지 실행되던 문제를 수정
- vim 모드: 외부 편집기(Ctrl+G)에서 편집한 후 NORMAL 모드의 `x` 또는 `r`이 더 이상 프롬프트 끝에 있는 붙여넣은 텍스트 자리 표시자를 분해하지 않도록 수
