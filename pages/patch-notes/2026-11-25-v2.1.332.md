## 변경사항

- MCP server의 기술(skill)이 추가되었습니다. 이들은 `/` 메뉴에서 `server:skill`로 표시되며, 다른 기술들은 기존 이름을 유지합니다
- 기술이나 명령어의 inline shell command를 거부할 수 있는 `PreSkillShellCommand` hook event가 추가되었습니다. 2.1.331 이전 버전에서는 이를 명시하는 설정 파일이 시작 시 대화창을 엽니다
- 다른 세션의 보류된 메시지에 대한 프롬프트에 "Always deliver"가 추가되었습니다
- 플래그된 메시지가 다른 모델에서 세션을 사용 중일 때 유지되는 footer line이 추가되었습니다. `/model`로 선택할 때까지 표시됩니다
- 응답 로깅이 활성화되었을 때 SendUserMessage 또는 Cowork의 message tool을 통해 Claude가 보낸 텍스트에 대한 OpenTelemetry `assistant_response` event가 추가되었습니다
- VS Code 및 Desktop의 Code tab에서 세션의 일부를 저장할 수 없을 때 경고가 추가되었으며, `/compact`로 저장하는 방법을 안내합니다
- VS Code 및 Desktop의 Code tab에서 재개된 세션의 초기 메시지가 로드되지 않았을 때 알림이 추가되었습니다. 이는 터미널에도 표시됩니다
- 시작 header에 Cyber Verification Program 액세스 tier가 추가되었습니다. claude.ai 계정으로 로그인했을 때 해당 tier가 모델에 적용되면 모델 이름 옆에 표시됩니다
- `claude auth login`이 claude.ai 로그인을 저장할 수 없을 때 `Login successful.`를 보고하던 문제가 수정되었습니다. 이제는 종료 코드 1을 반환하고 lock file 또는 디스크 부족 등 확인할 사항을 알려줍니다
- 반복된 auto-compaction 실패 시 named pipe가 아무것도 쓰지 않을 때(예: locked secrets manager로 마운트된 `.env`) Read, @-mentions 및 compaction이 멈추던 문제가 수정되었습니다. 이제는 20초 후에 읽기가 실패합니다
- 반복된 auto-compaction 실패 후 "Prompt is too long"으로 끝나는 turn이 고쳐졌습니다. context limit에서 추가 compaction이 처리할 수 있었을 경우입니다
- compaction이 summary를 output limit을 넘어 실행하도록 했을 때 실패하던 문제가 수정되었습니다. 세 번의 cutoff 회신 후 마지막 시도는 이제 더 짧은 summary를 요청합니다
- 긴 명령어에 대해 여러 wildcard가 있는 permission rule 또는 hook condition을 확인할 때 발생하는 freeze가 수정되었습니다
- hook이 끝나지 않는 출력을 print할 때 발생하는 freeze 및 runaway memory 사용이 대부분의 경우 수정되었습니다
- hook이 turn 중이나 `/compact` 후 차단되거나 실패했을 때 매우 큰 log에서 발생하던 freeze 및 context overflow가 수정되었습니다. 약 50,000자를 초과하는 텍스트는 이제 단축됩니다
- local MCP server가 standard output을 대량으로 전송할 때 terminal이 freeze되고 Ctrl+C를 무시하던 문제가 수정되었습니다
- 프롬프트 또는 piped input에 `@` 다음에 매우 긴 unbroken string(예: embedded font가 있는 minified CSS)이 있을 때 발생하던 freeze가 수정되었습니다
- 큰 tracked file이 재작성된 후 rewind point를 열 때 발생하던 긴 freeze가 수정되었습니다
- SSE MCP server가 event stream이 끊어지고 새로운 endpoint로 돌아오거나 전혀 돌아오지 않을 때 모든 tool call을 거부하거나 hang하던 문제가 수정되었습니다. 수동으로 reconnect할 때까지 발생합니다
- Remote Control이 desktop app, VS Code 또는 Agent SDK에서 세션을 대화창이나 MCP server의 질문을 대기 중인 것으로 표시하던 문제가 수정되었습니다
- usage limit이 Remote Control, IDE 및 SDK client에 이미 reset된 후에도 도달한 것으로 보고되던 문제가 수정되었습니다
- EnterWorktree로 세션이 `.claude/worktrees` 아래의 worktree로 이동하거나 거기서 재개된 후 대부분의 경우 CLAUDE.md 및 rules 파일이 모델에 두 번째로 전송되던 문제가 수정되었습니다
- 재시작된 세션에서 permission prompt를 거절한 후 claude.ai chat의 summary line에서 실행되지 않은 tool call이 완료된 것으로 계산되던 문제가 수정되었습니다
- Linux: Claude가 file을 그것을 통해 읽은 후 Bash edit diff가 변경되지 않은 symlink를 편집된 것으로 표시하던 문제가 수정되었습니다
- 세션 재개 및 `/stats`가 transcript에 많은 손상된 line을 포함할 때 수 초 동안 freeze되던 문제가 수정되었습니다
- `--fallback-model`의 `sonnet` 같은 family name이 `availableModels`가 오직 그것의 이전 버전만 허용할 때 삭제되던 문제가 수정되었습니다
- `/stats`가 큰 session transcript를 읽을 때 key가 수 초 동안 lag되던 문제가 수정되었습니다. 대화창 닫힌 후에도 발생하며, debug logging이 켜져있고 language server가 stderr를 대량으로 전송할 때도 발생합니다
- cloud가 default model을 거부했을 때 session이 실패하던 문제가 수정되었습니다. `availableModels` 리스트가 그것 또는 그 family의 이전 모델을 명시하지 않았을 경우입니다
- 강제된 이전 모델 리스트가 Google Cloud의 Agent Platform 및 Foundry에서 첫 번째 모델이 거부될 때 실패하던 문제가 수정되었습니다. 이제는 그 family의 다음 모델로 step down합니다(newest first로 나열된 경우)
- Bedrock, Google Cloud의 Agent Platform 및 Foundry에서 `opus`가 gateway를 통해 모델을 거부할 때 실패하던 문제가 수정되었습니다. 이제는 응답하는 이전 모델로 step down합니다
- Bedrock 및 Google Cloud's Agent Platform의 start-up model upgrade offer가 `availableModels` 리스트에서 제외한 모델의 이름을 지으던 문제가 수정되었습니다
- Bedrock sub-agent가 parent의 region에서 모델 profile이 없을 때 실패하던 문제가 수정되었습니다. 이제는 모델 자체의 profile을 사용하며, 그것은 그 region 외부에 있을 수 있습니다
- Foundry session이 admin의 리스트가 `sonnet`, `opus` 또는 `haiku`가 가리키는 버전을 차단할 때 모델 family를 떠나던 문제가 수정되었습니다. 이제는 built-in 또는 mapped name 아래 그것의 newest allowed version을 사용합니다
- Bedrock Mantle의 `sonnet` alias가 Haiku 4.5로 resolve되던 문제가 수정되었습니다. 이제는 Sonnet 5.5가 아니라 Sonnet 5를 의미하며, Sonnet 5가 없는 계정은 오류를 받습니다. 먼저 enable하세요
- prompt에서 Ctrl+C가 새로운 turn을 시작하던 문제가 수정되었습니다. stopped 상태인 background agent가 읽지 않은 subagent report를 가졌을 때입니다. 또한 double Ctrl+C가 종료되지 않던 문제도 수정되었습니다
- `/install-github-app`이 Esc로 돌아간 후 workflow를 다시 tick하던 문제가 수정되었습니다
- 10,000자를 초과하는 dictated text가 손실되던 문제가 수정되었습니다
- non-streaming retry가 broken response를 받거나 interrupted되었을 때 raw "JSON Parse error" 및 "The operation was aborted." API error가 수정되었습니다
- macOS에서 Claude Code의 window 또는 허용된 app이 활성화되어 있을 때 Esc가 action 사이의 computer use를 멈추지 못하던 문제가 수정되었습니다. 그 app의 popup용 Esc는 이제 computer use를 대신 멈춥니다
- helper command(API key helper 등)가 time limit을 초과 실행했을 때 발생하던 rare hang이 수정되었습니다
- fullscreen에서 텍스트를 선택할 때 footer의 right-hand label이 두 번째 행으로 밀려나던 문제가 수정되었습니다. 이는 텍스트를 마우스 아래로 이동시켜 잘못된 line을 복사할 수 있었습니다
- PreToolUse hook의 reason이 terminal Read, Grep, Glob, Edit 및 Write prompt에 표시되지 않던 문제가 수정되었습니다(anthropics/claude-code#102892, anthropics/claude-code#105343)
- 다운로드한 plugin을 제자리에 복사할 수 없을 때 `~/.claude/plugins/cache`에 `temp_*` 폴더가 쌓이던 문제가 수정되었습니다
- `CLAUDE_CODE_EFFORT_LEVEL`이 같은 level로 설정되었을 때 `--environment`와 함께 interactive session을 시작할 때 `--effort`가 무시되던 문제가 수정되었습니다
- headless 및 cloud session이 foreground fork의 Agent call을 fork가 시작된 순간 완료된 것으로 보고하던 문제가 수정되었습니다
- local MCP server가 Remote Control session의 process가 restart된 후 새로운 session ID를 보던 문제가 수정되었습니다
- idle compaction이 subscriber가 여전히 주간 한도 훨씬 아래일 때 skip되던 문제가 수정되었습니다
- @-mentioned text file이 extension을 가졌을 때 첫 2,000줄이 read limit을 초과하면 silently dropped되던 문제가 수정되었습니다. Claude는 이제 그것의 size 및 읽는 방법을 알게 됩니다
- plugin "not cached" error가 `/plugin` 대신 `/reload-plugins`(plugin을 다시 로드하는 명령어)를 가리키던 문제가 수정되었습니다
- self-hosted runner session이 machine의 git config에 `includeIf "gitdir:"` 또는 (git 2.44 to 2.46) `"onbranch:"` section을 가졌을 때 Anthropic-managed git에서 첫 번째 clone에 실패하던 문제가 수정되었습니다
- "You've used" 또는 "You've hit your" 같은 phrase로 시작하는 reply가 red usage limit error로 표시되던 문제가 수정되었습니다
- resumed conversation이 Bedrock, Google Cloud's Agent Platform, Foundry 및 기타 third-party provider에서 crash 또는 kill 후 마지막 메시지를 놓치던 문제가 수정되었습니다
- NotebookEdit이 edit이 cell의 type을 변경할 때 invalid notebook을 저장하던 문제가 수정되었습니다. attachment를 가진 cell을 code로 변환하는 것은 이제 거부됩니다
- 독립 실행형 Claude에서 design system으로 이동된 긴 README가 Claude가 deck 또는 design을 시작할 때 로드할 file 리스트를 잃던 문제가 수정되었습니다
- server의 task ID가 128자를 초과할 때 MCP tool call이 "malformed task handle"로 실패하던 문제가 수정되었습니다. 이제는 최대 1,024자까지의 ID가 작동합니다
- Self-hosted runner: `--configure-git`이 hung `git --version`을 PATH에 없는 git으로 보고하던 문제가 수정되었습니다
- 여러 task를 한 번에 delete 또는 update했을 때 task id가 재사용되고 deleted task가 돌아오던 문제가 수정되었습니다. TaskGet도 completed task를 blocker로 나열하던 문제도 수정되
