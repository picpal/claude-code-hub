> 원문: [Claude Code v2.1.292 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.292)

## 변경사항

- `claude plugin install`에 `--marketplace <source>`를 추가했습니다: 필요한 경우 marketplace를 추가하고, `claude plugin marketplace add`와 동일한 정책 검사를 거친 후 해당 marketplace에서 플러그인을 설치합니다
- Agent tool에 `effort` 매개변수를 추가했습니다: Claude가 요청하는 effort 수준에서 sub-agent를 실행합니다
- `CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS` 환경변수를 추가했습니다: 오버로드된(529) 요청을 재시도할 때 백오프의 더 긴 기본 지연을 설정합니다
- `prompt.autocomplete`를 추가했습니다: mod가 prompt box의 자동완성 목록에 자신의 행을 추가하기 위해 훅할 수 있는 이벤트입니다
- `$.model.complete`에 prompt caching을 추가했습니다(mod용): `prompt`와 `system`은 텍스트 블록을 받고, 블록의 `cache: true`는 해당 블록까지의 요청을 캐시합니다
- `agent.spawn` mod hook에 workflow agents를 추가했습니다(run 및 index 포함): mod가 이들을 거부할 수 있습니다
- `permissionMode: auto`를 사용한 subagent 정의가 auto mode를 사용할 수 없을 때(설정에 의해 비활성화되었거나, circuit breaker 또는 지원하지 않는 model인 경우) auto mode로 진입하는 문제를 수정했습니다
- sandboxed commands가 `~/.claude/seed-admin` 아래의 `/ultrareview` uploads의 staged file copies를 읽을 수 있던 문제를 수정했습니다
- managed sandbox read-deny path(및 그 옆의 사용자 path)가 세션 중 나타나거나 다시 포인트될 때 그 안의 project grants를 삭제하거나 그것이 포함하는 파일로부터의 credential injection을 종료하지 않던 문제를 수정했습니다
- macOS 및 Windows의 notebook 또는 PDF 읽기가 mid-read에 스왑된 링크를 통해 승인된 것 외의 파일을 반환할 수 있던 문제를 수정했습니다
- server-managed settings의 tampering된 on-disk cache가 settings fetch에 실패했을 때 built-in policy plugin을 끄거나 제거할 수 있던 문제를 수정했습니다
- home folder 또는 drive의 8.3 short name 또는 다른 alternate Windows spelling에서 `rm -rf`를 실행할 때 이를 제거하는 것으로 처리하지 않던 문제를 수정했습니다
- 보안: PreToolUse hook approvals 및 auto mode가 network(UNC) paths에서 file reads의 permission prompt를 우회하던 문제를 수정했습니다
- skill 또는 slash command의 `allowed-tools` rule이 auto mode 또는 plan mode를 mid-turn에 벗어날 때 이후 turn에서 돌아오던 문제를 수정했습니다
- `HTTPS_PROXY`가 설정되어 있을 때 `NO_PROXY`가 Claude Code의 자체 API requests(sign-in, policy, feedback, artifacts)에 대해 무시되던 문제를 수정했습니다
- 128자보다 긴 이름의 MCP tool이 모든 요청을 실패하게 하던 문제를 수정했습니다: 이제 해당 tool은 제외되고 MCP error가 이름을 표시합니다
- `claude plugin` commands(예: `marketplace add` 및 `install`)가 첫 실행 시 organization의 managed settings가 로드되기 전에 실행되던 문제를 수정했습니다
- one-shot `claude -p` 및 Agent SDK runs가 최종 결과 5초 후 background command를 중지하고, one-shot `claude -p` runs가 scheduled wakeup을 드롭하던 문제를 수정했습니다: 이제 둘 다 대기합니다
- `claude --resume` session picker 또는 `/resume`에서 session을 재개할 때 plan mode가 복원되지 않던 문제를 수정했습니다
- `/resume`, `/branch` 또는 `/clear` 이후에 생성된 saved scheduled tasks가 절대 실행되지 않고, saved tasks가 tasks file에 대한 2번의 쓰기가 milliseconds 떨어져 있은 후 이후 creates 및 deletes를 무시하던 문제를 수정했습니다
- background session의 `/loop`가 session의 프로세스가 재시작될 때(예: 충돌 후) silently 중지되던 문제를 수정했습니다: pending wakeup이 손실되었기 때문입니다
- Grep 및 Glob이 주어진 파일 또는 폴더를 읽을 수 없을 때 일치하는 항목이 없다고 보고하던 문제를 수정했습니다: Claude는 이제 한 번 재시도하거나 알려줍니다
- Read tool이 PDF의 `pages`가 "6,9,15"와 같은 list일 때 error 없이 첫 번째 entry만 반환하던 문제를 수정했습니다: 이제 각 page 또는 range를 따로 읽도록 하는 error를 반환합니다
- @-mentioned text files over 256KB가 silently 생략되던 문제를 수정했습니다: Claude는 이제 파일의 size를 알려받고 portions에서 읽습니다
- agents가 main conversation을 이미 중지한 limit에서 실패할 때 usage limit alert가 background agent당 한 번 반복되던 문제를 수정했습니다
- Remote Control viewers가 desktop app 또는 IDE에서 호스팅된 sessions에서 background subagents의 빈 subagent pane을 보던 문제를 수정했습니다
- cross-session delivery notices가 유사한 이름의 두 sessions를 하나의 recipient로 표시하고, expiry notice가 terminal session이 message를 lapse하게 할 때 desktop app을 비난하던 문제를 수정했습니다
- desktop app의 Send now가 다른 message가 이미 queued되어 있을 때 turn이 대기 중인 subagent를 종료하던 문제를 수정했습니다
- `/bug`, `/share` 및 `/feedback <text>`가 report 전송 중 Ctrl+O 또는 Ctrl+Z 후 다시 시작되고, 전송된 후 cancelled로 닫히던 문제를 수정했습니다
- `/remote-env`가 Enter를 즉시 누를 때 saved default environment를 교체하던 문제를 수정했습니다: 이제 list가 default에서 열리고, no default이 적용되면 행에 check mark이 없습니다
- 일부 pasted text가 한 prompt에서 여러 pastes가 겹칠 때 typed text로 Claude에 도달하던 문제를 수정했습니다
- vim mode가 line의 끝 너머에 cursor를 남기고, j/k가 shorter lines에서 column을 잃고, `f`/`t`/`F`/`T`/`;`/`,`가 prompt의 다른 line의 match로 jump하거나 delete하던 문제를 수정했습니다
- `/add-dir` path box가 Shift+Enter 또는 paste에서 line break를 추가하고, fast-typed "tab", "up" 또는 "down"을 해당 keys로 처리하던 문제를 수정했습니다
- fast typing, input-method text 및 decomposed accents가 prompt footer row를 선택한 동안 드롭되고, `!`가 row를 선택된 상태로 남기던 문제를 수정했습니다
- fullscreen mode가 매 window resize와 iTerm2가 감지될 때 Ctrl+L에서 full-screen clear를 전송하여 iTerm2의 scrollback을 stale pages로 채웠을 수도 있던 문제를 수정했습니다
- Read deny rule이 설정되고 working directory가 symlink 아래에 있을 때 파일을 이름으로 지정하지 않는 @-words에 대한 spurious "could not be examined" note를 수정했습니다
- "instruction file not loaded" lines이 `/cd` 또는 permission 변경 후 stale하거나 누락되던 문제를 수정했습니다: nested one이 로드되지 않으면 transcript line을 추가했습니다
- 반복된 `/name`을 가진 compaction summary가 Claude가 user용으로 예약된 skill을 호출하게 하던 문제를 수정했습니다
- Write, Edit, NotebookEdit 및 LSP rows와 단일 Read, Grep 및 Glob rows가 mod가 call을 거부한 이유를 숨기던 문제를 수정했습니다: 이제 row가 이유를 표시합니다
- cloud session이 turn이 정확히 끝날 때 worker가 중지되었을 때 절대 끝나지 않은 turn을 표시하던 문제를 수정했습니다
- 큰 transcript를 가진 cloud sessions이 approval이 승인된 후 permission을 다시 요청하던 문제를 수정했습니다
- cloud sessions에서 Claude가 scheduled tasks 및 기타 queued notifications을 읽는 동안 message를 재시도하거나 수정할 때 scheduled tasks 및 다른 queued notifications이 손실되던 문제를 수정했습니다
- cloud session의 container가 재시작되었을 때 cloud sessions이 client에서 선택한 thinking setting을 잊던 문제를 수정했습니다
- Cowork cloud sessions이 Anthropic이 organization의 settings를 확인할 수 없을 때 proxy가 artifacts를 차단했다고 말하던 문제를 수정했습니다
- hooks module이 하나의 const를 통해 많은 `$.state` calls를 만드는 plugins가 로드하거나 검증하는 데 분 단위로 시간이 걸리던 문제를 수정했습니다
- `claude plugin validate`가 engine이 다른 곳에서 읽는 hooks module의 matcher 또는 state value를 나열하던 문제를 수정했습니다
- `claude plugin validate`가 top-level `var`를 통해 읽은 `$.state` value를 나열하는 문제를 수정했습니다(이는 선언 또는 재할당된 경우): 이제 해당 module이 거부됩니다
- plugin의 served `$` method가 hook origin을 재시작하여 `.catch`를 가진 guard hook이 끝 없이 다시 실행될 수 있던 문제를 수정했습니다
- plugin hooks worker가 재시작되는 동안 만든 plugin interface calls가 다른 plugins가 put한 hooks 없이 실행되던 문제를 수정했습니다
- mod의 `config.set`, `state.set`, `env.set` 또는 `agent.spawn` hook이 `next(e)`를 호출한 후 거부할 때 refusal로 응답되던 문제를 수정했습니다: 이제 hook이 실패로 보고됩니다(이름으로)
- `/theme`, `/config` Theme menu 및 first-run theme step이 plugin의 `config.set` hook을 물어보기 전에 theme을 저장하던 문제를 수정했습니다
- plugin의 `tool.check` hook이 answer를 요구하는 tool을 실행할 수 있도록 allow로 응답하던 문제를 수정했습니다(question, plan approval): dialog을 표시하지 않았습니다
- mod의 start-up prompt, command 또는 subagent가 hooks worker를 교체할 때 두 번째로 queued되던 문제를 수정했습니다
- mod의 hook이 `next(e)`를 호출한 후 turn이 interrupted되는 동안 실패하여 call을 통과시키던 문제를 수정했습니다: 이제 call이 거부됩니다
- plugin의 prompt drop 또는 setting deny가 그 reason이 4,096자보다 길 때 무시되던 문제를 수정했습니다
- organization의 plugin이 자신의 reload에서 언로드되거나, 다른 plugin이 충돌한 후, user-installed mod이 추가한 `$` name을 반환할 때 언로드되던 문제를 수정했습니다: 이제 mod이 언로드됩니다
- plugin hooks worker가 재시작되는 동안 만든 tool calls가 plugins의 permission hooks 없이 응답되던 문제를 수정했습니다
- plugin `tool.call` hooks이 misnamed parameters가 수리되기 전에 일부 tool calls를 보던 문제를 수정했습니다: hook은 이제 tool이 실행할 arguments를 봅니다
- mod의 guard hook이 `.catch`를 가지고 있을 때 다른 mod의 hook이 guard의 자체 `$` call 아래에서 만드는 calls에 대해 silently 건너뛰던 문제를 수정했습니다: 이제 `.catch`가 물어집니다
- `claude -p` 및 SDK sessions의 startup을 개선했습니다: 첫 turn이 더 이상 HTTP 및 SSE MCP servers가 `resources/list`에 응답하기
