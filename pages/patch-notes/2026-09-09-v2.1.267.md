> 원문: [Claude Code v2.1.267 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.267)

## 변경사항

- `maxEffortLevel` 설정을 추가했습니다(최상위 수준 또는 `modelSettings` 아래 모델별): Bedrock, Vertex 및 Foundry를 포함한 모든 provider의 effort level을 제한하며, 사용자는 여전히 더 낮은 수준을 선택할 수 있습니다
- `--system-prompt-snapshot off`를 추가했습니다. 대화에 기록된 prompt를 재사용하는 대신 매 요청마다 system prompt를 새로 렌더링합니다(prompt 텍스트 반복 작업용)
- Cowork 예약 작업이 관리형 설정에서 샌드박싱을 요구하는 조직의 클라우드에서 시작 시 실패하는 문제를 수정했습니다
- `/context` 및 기타 로컬 command 출력이 모바일 클라이언트에서 공백으로 렌더링되는 문제를 수정했습니다
- agent view 내 tmux 또는 ssh 세션에 다시 연결한 후 shift+enter 및 option+backspace가 작동하지 않는 문제를 수정했습니다
- 전체 화면 모드에서 위로 스크롤할 때 dim last-prompt 헤더가 대화의 맨 위에 나타나지 않는 문제를 수정했습니다
- Workflow `agent()` 호출이 large output schema를 사용할 때 auto mode에서 거부되는 대신 safety classifier로 확인되도록 수정했습니다
- marketplace entry path에 backslash가 포함되어 있을 때 macOS 및 Linux에서 fetched marketplace의 containment check를 우회할 수 있는 경우를 수정했습니다
- Claude Desktop 같은 host app에서 만료된 AWS 또는 Google Cloud credential이 re-authenticate 오류가 나타나기 전에 generic "request failed" 메시지와 함께 열 번 재시도하는 문제를 수정했습니다
- `-p --resume`을 통해 `/compact` 또는 다른 slash command를 실행한 후 세션을 재개할 때 거짓 "Continue from where you left off." turn이 삽입되지 않도록 수정했습니다
- 대용량 세션을 재개할 때(transcript 5MB 초과): parallel tool call 및 해당 hook output이 더 이상 reloaded conversation에서 버려지지 않습니다
- 관리형 `allowedHttpHookUrls`, `httpHookAllowedEnvVars` 및 `allowedChannelPlugins`를 읽을 수 없을 때 모든 항목을 허용하는 대신 아무것도 허용하지 않도록 수정했습니다
- 관리형 설정에서 Claude apps gateway sign-in을 요구하는 시스템에서 `/login`을 실행할 때 Esc로 대화상자를 닫을 수 있도록 수정했습니다(이전에는 아무것도 수행하지 않음)
- 업로드 중단으로 인해 잘린 artifact publish가 이제 Claude Code가 업로드가 완료되지 않았음을 알 때 한 번 재시도하며, unknown outcome을 보고하는 대신 재시도합니다
- 기본 effort가 여전히 고정된 모델(Opus 4.7, Opus 4.8, Fable 5)에서 custom command, skill 및 subagent의 `effort:` frontmatter가 무시되는 문제를 수정했습니다
- page file이 유효한 UTF-8이 아니거나 replacement character(U+FFFD)를 포함하는 경우 artifact publish가 유용하지 않은 오류로 실패하던 문제를 수정했습니다. 이제 오류 메시지에 수정할 line 및 column을 표시합니다
- `claude agents` `@` directory menu가 세션 시작 후 생성된 repository를 나열하지 않는 문제를 수정했습니다
- Claude Desktop 또는 VS Code 세션에 joining한 Remote Control client가 다시 변경할 때까지 stale permission mode를 표시하는 문제를 수정했습니다
- `claude remote-control`의 server credential이 만료되면(시작 후 약 30일) 모든 attached session을 exit하고 drop하는 문제를 수정했습니다. 이제 host가 다시 등록하고 계속 진행합니다
- 서로 다른 model이나 mode에 대한 요청이 서로 다른 limit window를 보고할 때 세션 중에 usage-limit warning이 깜빡이는 문제를 수정했습니다
- MCP server가 다시 전송하거나 built-in tool이 다시 렌더링할 때 model이 이미 로드한 tool에 대해 earlier reasoning이 버려지는 문제를 수정했습니다
- 대화 중간에 사라지는 tool(disconnected MCP server 또는 업그레이드로 인해)이 tool list를 다시 쓰고 earlier thinking을 버리는 문제를 수정했습니다
- 대화에서 forked된 background worker가 세션 중간에 EnterWorktree를 대화의 tool block에 추가하여 prompt-cache 재사용이 끊기는 문제를 수정했습니다
- ToolSearch가 없는 세션에서 mid-session MCP 및 plugin tool이 tool list에 추가되어 prompt-cache 재사용이 끊기는 문제를 수정했습니다. 이제 지원되는 model이 이를 deferred definition으로 수신합니다
- /model을 사용해 model을 전환할 때 모든 tool definition을 다시 전송하는 문제를 수정했습니다(prompt-cache miss). 이제 commit 및 PR attribution 텍스트가 model 변경 시 업데이트되는 대화 note로 도착합니다
- resumed session이 MCP connector가 이전과 다른 시점에 다시 연결될 때 inline tool set을 다시 쓰는 문제를 수정했습니다
- resumed session이 첫 번째 turn에서 tool을 실행했을 때 기록된 tool description 대신 tool description을 다시 렌더링하는 문제를 수정했습니다
- claude.ai connector의 tool이 세션과 resume 사이에 변경될 때 prompt-cache miss 및 dropped extended thinking을 수정했습니다
- resumed session이 connector가 다시 연결되기 전에 earlier MCP tool announcement를 다시 쓰고(extended thinking을 버리는) 문제를 수정했습니다
- print-mode(`-p`) 대화를 interactively하게 resume할 때 prompt-cache break를 수정했습니다. 이제 system prompt prefix가 변경되지 않습니다
- `/diff` panel을 개선했습니다. 이제 "0 files changed" 및 spinner를 깜빡이지 않으며 settle되고, empty state가 panel에 centered됩니다
- Bash tool의 설명 guidance를 개선했으므로 Claude가 command를 echo하는 대신 plain words로 command가 수행하는 작업을 설명합니다
- sandbox guidance를 개선했으므로 Claude가 sandbox 내에서 `pbcopy` 같은 clipboard command가 실패할 때 `/copy`를 제안합니다
- 많은 Bash tool call이 있는 세션의 `--resume` first-render time을 개선했습니다
- prompt input responsiveness를 개선했습니다. 이제 keystroke가 spinner 또는 streaming repaint 뒤에서 frame을 기다리지 않습니다
- prompt-cache stability를 개선했습니다. `--system-prompt` 또는 `--append-system-prompt`로 시작된 subagent 및 세션이 이제 system prompt 및 tool definition을 한 번만 기록하고 다시 렌더링하지 않습니다
- Artifact tool publish error를 개선했습니다. publish가 거부되면 메시지에 이유 및 대처 방법이 표시됩니다
- Self-hosted runner: `--use-anthropic-git-proxy`를 server에 등록할 때 보고되고 legacy git proxy를 통해 clone하는 각 세션에 대해 warning을 출력하도록 변경했습니다
- Gateway: `forward_user_identity` upstream을 email이 forwarded된 developer에게 429를 그대로 반환하도록 변경했습니다(다음 upstream으로 failover하지 않음). 이렇게 하면 proxy의 per-user limit이 유지됩니다
- [VSCode] saved transcript가 cyclic parent link를 포함하는 대화에서 fork, edit of earlier message 또는 rewind를 수행할 때 extension host가 100% CPU에서 hang하는 문제를 수정했습니다
- [VSCode] WSL2/WSLg에서 screenshot를 paste할 때 raw image bytes가 chat input에 삽입되는 문제를 수정했습니다. 이제 clipboard가 image를 제공하면 첨부되고, 그렇지 않으면 paste가 무시됩니다
- [VSCode] chat diff block이 항상 dark editor theme으로 렌더링되는 문제를 수정했습니다. 이제 active VS Code color theme(high contrast 포함)을 따릅니다
- [VSCode] mixed right-to-left 및 English text가 message input에 입력할 때 잘못된 순서로 렌더링되는 문제를 수정했습니다
- [VSCode] Windows(CRLF) line ending이 있는 file에서 diff view의 edit을 수락할 때 "String not found in file" error로 실패하는 문제를 수정했습니다
- [VSCode] @-mention이 path에 공백이 있는 file을 drop하는 문제를 수정했습니다
- [VSCode] workspace folder가 remote host에만 있을 때 Remote-SSH로 연결된 window에서 sessions list view가 load되지 않는 문제를 수정했습니다
- [VSCode] 큰 또는 symlink-heavy workspace에서 file을 볼 때 runaway ripgrep process를 수정했습니다
- [Claude Code on the web] GitHub Enterprise Server 세션이 token이 만료되면 GitHub account가 disconnected로 표시되는 문제를 수정했습니다. 이제 PR 및 issue 작업이 자동으로 refresh됩니다
- [Claude Code on the web] Claude GitHub App가 없는 조직에서 `gh` 및 GitHub API 호출이 실패하는 문제를 수정했습니다. 이제 connected GitHub account를 사용하고 연결된 account가 없을 때 이를 알립니다
- [Claude Tag] Claude Tag admin settings의 preset connection form에 "Use a custom connector" link를 추가했으므로 처음부터 시작하지 않고 custom connection으로 전환할 수 있습니다
- [Claude Tag] 조직의 usage credit이 부족하면 Claude가 "The API rejected the request as invalid"로 답변하는 문제를 수정했습니다. 이제 답변에 이를 명시하고 더 추가하는 방법을 설명합니다
- [Claude Tag] channel 최상위 수준에서 Claude가 post한 message를 edit 또는 delete하려는 thread request가 correction으로 답변되는 대신 해당 message를 post한 세션에 도달하도록 수정했습니다
- [Claude Tag] Admin settings > Review requests에서 Tool access request의 **Connect**가 "Authorization failed"로 실패하거나 requested access bundle이 deleted로 표시되는 문제를 수정했습니다
