## 변경사항

- macOS와 Linux에서 샌드박스된 Bash 명령어가 각 명령어 이전에 샌드박스 외부의 셸 시작 파일을 실행하던 문제 수정
- macOS 샌드박스 `denyWrite` glob 패턴이 패턴의 폴더가 symlink를 통해 도달할 때 경로의 실제 위치에 적용되지 않던 문제 수정
- 샌드박스된 명령어 및 자동 수락된 편집이 `--mcp-config`로 전달된 MCP config 파일을 수정할 수 있던 문제 수정
- 비활성화된 MCP server가 print 및 SDK 세션에서 이후의 권한 프롬프트에 의해 다시 연결되던 문제 수정
- Bash 권한 확인이 리디렉트 실패 가능성이 있는 명령어에 의해 설정된 변수를 신뢰하던 문제 수정
- Bash 권한 확인이 plain `cd`처럼 `cd`가 래핑되거나 접두어가 붙은 디렉터리 변경 후 git을 실행하는 일부 복합 명령어에 대해 프롬프트를 표시하지 않던 문제 수정
- `Edit(path)` deny 규칙이 subshell도 보유한 일부 명령어에서 해당 경로로의 Bash 리디렉트를 차단하지 못하던 문제 수정
- worktree로 격리된 세션이 격리 보호 기능이 거부해야 하는 일부 로케일 접두어 명령어를 수락하던 문제 수정
- worktree로 격리된 zsh 세션이 격리 보호 기능이 거부해야 하는 일부 산술 명령어를 수락하던 문제 수정
- Claude Code가 생성하는 worktree 및 branch checkout이 다른 git 작업처럼 git replace refs를 무시하도록 수정
- config 디렉터리가 symlink를 통해 도달할 때 프로필 저장소 쓰기 보호가 적용되지 않던 문제 수정
- 매우 큰 중첩된 CLAUDE.md를 읽은 후 세션이 반복적으로 컴팩트되던 문제 수정; 크기 제한을 초과하는 중첩된 CLAUDE.md는 이제 시작 부분만 로드
- ctrl+enter(지금 전송)가 응답이 시작되기 전에만 메시지를 큐에 추가하던 문제 수정; 이 키가 해당 훅이 실행 중일 때 눌리면 프롬프트의 훅을 다시 시작하면서 메시지는 큐에 남겨진 문제 수정
- key-bound slash 명령어가 `!` mode의 셸에서 실행되던 문제 수정
- ctrl+o가 아직 전달 대기 중인 다른 agent 및 세션의 메시지를 표시하지 않던 문제 수정; 이제 대화 기록 아래에 완전히 표시되며 대기 중으로 표시
- 긴 tool 출력 미리보기가 emoji를 통과하여 잘려 `jq`가 파싱할 수 없는 세션 기록이 남겨지던 문제 수정
- Linux 샌드박스에서 부모의 `/proc`를 공유하는 경우 Read가 PDF 페이지 범위에 대해 "File does not exist" 보고하던 문제 수정
- Claude Desktop에서 호스팅되는 세션의 메시지가 연결이 새로고쳐질 때 손실되던 문제 수정
- Claude desktop app의 Claude Code 세션에서 같은 컴퓨터의 terminal이 다른 계정 또는 조직으로 로그인되었을 때 기능이 누락되던 문제 수정
- `claude remote-control` 상태 줄이 git 저장소에 있지 않은 폴더에 대해 `HEAD`를 branch로 표시하던 문제 수정
- split-pane agent teammate가 leader의 command line에서 주어진 tool deny 및 `--tools` 규칙을 상속받지 않던 문제 수정
- `/rename`으로 이름을 바꾼 세션이 VS Code 창 다시 로드 또는 비대화형 `--resume` 후 다른 세션에서 생성된 이름으로 나타나던 문제 수정
- `/rewind` 목록이 `/code-review --fix`, subagent 또는 셸 명령어를 통해 체크포인트된 파일을 변경한 턴에 대해 "No code changes"를 표시하던 문제 수정
- `/privacy-settings`가 오래된 "Help improve our AI models" 값을 표시하던 문제 수정; 이제 설정을 가져올 수 없을 때도 표시
- 조직이 피드백을 수락하지 않을 때 피드백이 "try again later"라고 말하던 문제 수정; 이제 server의 이유와 버그 보고 위치를 표시
- oversized /feedback 보고서가 실패하는 대신 기록 없이 다시 전송되지 않던 문제 수정
- `--add-dir` 폴더의 skill이 다른 skill이 이미 해당 이름을 보유하고 있을 때 도달 불가능하던 문제 수정; 이제 `<folder>:<name>`으로 제공
- `/verify` 및 `/code-review`가 파일이 셸에서 변경된 중첩 package의 자체 skill을 찾지 못하던 문제 수정
- /claude-api skill이 `ant beta:worker poll --on-work`가 trace context를 명령어에 전달한다고 말하던 문제 수정
- /claude-api skill의 C# tracing 설정이 cloud platform client의 span을 누락하던 문제 수정
- /claude-api skill이 AWS의 Claude Platform에 대한 요청 API span이 호출자의 trace에 참여할 수 없다고 말하던 문제 수정
- PowerShell에서 실행되는 hook이 프로그램이 코드 2로 종료될 때 차단하지 않고, Windows에서 `PreToolUse` 및 `PermissionRequest` hook with `"shell": "powershell"`이 Git for Windows가 설치되지 않았을 때 열려 있는 상태로 실패하던 문제 수정
- `haiku`와 같이 alias로 모델을 명명하는 mod의 `turn.step` hook이 모델 오류로 모든 요청을 실패하던 문제 수정; 이제 alias가 모델로 확인
- claude.ai에서 동기화된 plugin 및 skill이 디스크 읽기 오류 후 제거되고 때로는 세션 중간에 제거되던 문제 수정
- artifact 게시 및 업데이트가 특정 축소된 script를 포함한 일반 페이지와 같은 일부 일반 페이지에 대해 거부되던 문제 수정
- 대화가 해당 턴에서 컴팩트된 후 나머지 턴에서 각 artifact 업데이트에 대해 권한 허용을 요청하던 문제 수정
- `ANTHROPIC_BEDROCK_BASE_URL`이 기본 `bedrock-runtime.<region>.amazonaws.com` endpoint로 설정되었을 때 fine-grained tool streaming이 Amazon Bedrock에서 꺼진 채로 유지되던 문제 수정
- keepalive ping만 전송하는 gateway 뒤에서 "Waiting for API response" 힌트가 깜빡이던 문제 수정: Anthropic의 backend에서 나가는 경로는 이제 45초를 대기
- Claude가 PR, issue 및 comment에서 role 이름과 placeholder를 mention으로 작성하여 관련 없는 GitHub 사용자에게 알림을 보내던 문제 수정
- Linux: 배경 명령어가 세션보다 오래 유지되었을 때 샌드박스 쓰기 deny가 해제되던 문제 수정
- Windows: PowerShell 권한 확인이 현재 디렉터리를 대상으로 하고 추가 인수를 포함하는 일부 `Set-Location` 또는 `cd` 명령어를 자동 승인하던 문제 수정; 이제 승인을 위해 프롬프트 표시
- macOS: Xcode 또는 Command Line Tools가 없는 Mac에서 Claude Code가 시작될 때마다 "Install Command Line Developer Tools" 대화상자가 열리던 문제 수정
- Self-hosted runner: `--startup-timeout-min`이 첫 프롬프트(예: `/code-review`)가 여전히 subagent에서 작동 중인 세션을 중지하던 문제 수정; frozen process는 여전히 중지
- Claude Code가 Windows에서 실행하는 많은 git 명령어의 속도 개선; 모든 플랫폼에서 이러한 명령어의 오류는 git이 다른 언어로 설정된 경우에도 영어로 표시
- hooks module을 로드하기에 너무 깊게 중첩되었을 때의 오류 개선: 이제 bare stack-overflow 메시지 대신 파일을 명명
- Disk-full 처리 개선: full disk에 의해 잘린 Bash 명령어는 이제 그렇다고 말하고 확보할 폴더를 명명하며, full temp 볼륨에서 시작하면 명확한 메시지를 출력하며 raw ENOSPC 오류는 표시하지 않음
- OpenTelemetry를 추가하도록 요청할 때 /claude-api skill을 개선하여 SDK tracing 외에 API tracing도 제공
- /claude-api skill을 개선하여 기능이 지원되지 않는다고 말하기 전에 live docs 확인
- Self-hosted runner: 새 runner로 이동하는 세션 개선: Claude는 이제 중단된 tool call을 보며 결과 불확실로 표시
- 번들된 dataviz skill을 업데이트하여 APCA를 텍스트 대비 측정으로 수락(AA 준수가 필요한 경우 WCAG 2 비율 유지), palette validator script에 `apca(text, background)` 함수 추가, colored chart fill 내부 label이 흰색 또는 near-black이어야 하는지 표시
- /claude-api skill 업데이트: service account key 및 Workload Identity Federation token이 이제 OpenTelemetry destination을 관리 가능
- `sed -i`를 변경하여 표준 Bash prompt를 가지고 시뮬레이션된 file-edit preview가 아닌 작성된 대로 실행; 다른 Bash edit처럼 더 이상 `/rewind`로 복원되지 않음
- `claude ultrareview`를 변경하여 workspace 신뢰를 요구: terminal에서 요청하며, 그렇지 않으면 거부; script는 `--trust-workspace`를 전달하며 값을 취하지 않음(이전에 PR 번호 또는 base branch 배치) 또는 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1` 설정
- 위험한 `rm` 및 `rmdir` prompt를 bypass permissions mode의 Desktop app 및 VS Code에서 변경하여 즉시 rewrite hint와 함께 명령어를 거부하므로 무인 세션은 계속됨
- 설정이 샌드박스에서 제외하는 명령어를 변경하여 샌드박스가 활성화되었지만 실행할 수 없을 때 write-list 경로에 쓰기 전에 물음; 언샌드박스된 fallback이 거기서 거부됨
- worktree 생성 및 재사용을 변경하므로 git이 더 이상 일반 clones 및 Bash sandbox가 구성된 partial clone에서 요청 시 object를 가져오지 않음; 이러한 partial clone은 먼저 object를 가져옴
- `/claude-api` skill을 변경하여 `coordinator` 대신 `multiagent_20261001`에서 Managed Agents subagent team을 빌드하며 기본적으로 dynamic workflow 활성화
- [VSCode] dictation 또는 extension의 자체 요청이 TLS-inspecting proxy와 같은 certificate verification에 실패할 때 수행할 작업을 말하는 log warning 추가
- [VSCode] editor가 해당 파일의 불완전한 복사본을 캐시한 후 Claude panel이 공백으로 유지되던 문제 수정; 이제 자동으로 복구되거나 잘못된 사항과 해결 방법을 표시
- [VSCode] 메시지를 전송하지 않고 새 세션을 시작할 때마다 Session history가 빈 "Untitled" 세션으로 가득 차던 문제 수정
- [VSCode] `/goal`과 같은 긴 slash-command 메시지가 chat panel을 가득 채
