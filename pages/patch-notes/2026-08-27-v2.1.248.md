> 원문: [Claude Code v2.1.248 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.248)

## 변경사항

- `--restricted` (또는 `CLAUDE_CODE_RESTRICTED=1`)를 추가했습니다: 명령어나 코드를 실행하는 built-in 도구와 `WebFetch`를 제거하고 (`--tools`에서 명시된 것 제외), 작업 디렉토리 내의 파일 도구만 유지하며, `bypassPermissions`을 거부하고, 사용자, 프로젝트 및 로컬 설정 파일을 무시합니다
- Agent frontmatter에 `experimental.cacheTtl` (`"5m"` 또는 `"1h"`)을 추가했습니다: subagent TTL 설정이 구성되지 않았을 때 사용되는 per-agent prompt cache TTL입니다
- `claude self-hosted-runner --client-label <label>` (또는 `SELF_HOSTED_RUNNER_CLIENT_LABEL`)을 추가했습니다: runner가 등록할 때 사용하는 레이블을 재정의합니다 (기본값: hostname)
- Server 관리 설정 진단을 추가했습니다: 설정 로드 실패 시 시작 경고, 로드 실패 또는 로드되지 않은 이유를 설명하는 `/doctor` 및 `/status` 라인 (Bedrock/Vertex/third-party provider, 사용자 정의 `ANTHROPIC_BASE_URL`)
- GitHub CLI token이 `workflow` scope를 충분하지 않을 때 `/web-setup`에서 경고를 추가했습니다: 매우 큰 저장소에 대한 푸시는 없으면 거부될 수 있기 때문입니다
- AWS Marketplace, self-serve Enterprise 및 Enterprise trial을 통해 청구되는 Enterprise 조직용 `/usage-credits`을 추가했습니다: 멤버가 관리자에게 더 높은 사용 제한을 요청할 수 있습니다
- Bedrock, Vertex 및 Foundry에서 동일한 머신의 세션 간 cross-session messaging (`SendMessage` / `ListAgents`)을 추가했습니다: 텔레메트리가 비활성화된 경우도 포함됩니다
- 긴 세션에서 약 1시간마다 prompt-cache miss (및 손실된 extended-thinking context)를 수정했습니다: OAuth token refresh 후 도구 정의가 다시 렌더링되기 때문입니다
- 계정이 사용 초과 상태로 진입했을 때 세션과 그 `--resume` 사이에서 `ScheduleWakeup` 도구 정의가 변경되어 재개된 세션의 첫 번째 턴에서 전체 prompt-cache miss가 발생하는 문제를 수정했습니다
- Claude Desktop과 Cowork 세션이 30일 후 사라지는 문제를 수정했습니다: 트랜스크립트 정리가 이제 앱에 있는 동안 데스크톱 작성 세션을 유지합니다 (조직 정책이 보존을 관리하지 않는 한); 새로운 `desktopSessionCleanupPeriodDays` 설정이 예외를 제한합니다
- 다른 Claude Code 프로세스가 token refresh lock을 보유하고 있을 때 세션 token이 만료되면 로그인 화면으로 전송되는 문제를 수정했습니다: 요청이 이제 재시도 가능한 오류로 실패합니다
- Windows: 세션에서 분리되거나 win32-input-mode로 남겨진 터미널 탭에서 시작될 때 `claude agents` 목록이 키보드에 응답하지 않는 문제를 수정했습니다
- `/login`의 권장 Console 로그인이 `ANTHROPIC_API_KEY` 또는 API 키 helper가 설정된 머신 등에서 사용할 수 없는 경우 로그인 URL을 표시하기 전에 OAuth 오류로 실패하는 문제를 수정했습니다: 이제 API-key 로그인으로 폴백됩니다
- `/model` 및 fast-mode 전환 알림의 모델 이름을 코드로 렌더링하도록 수정했습니다: `[1m]` 같은 접미사가 링크가 아닌 문자 그대로 표시됩니다
- `CI` 환경 변수가 설정되었을 때 `claude agents`가 workspace 신뢰 프롬프트를 건너뛰는 문제를 수정했습니다
- PR-status cache에 잘못된 항목이 있을 때 `claude agents`가 시작 시 충돌하는 문제를 수정했습니다
- 머신이 꺼져 있었을 때 agent view가 몇 주 된 background 세션을 부활시키는 문제를 수정했습니다: 이제 그러한 세션은 실제 종료 시간에 중지된 것으로 표시되며, 열면 저장된 대화를 재개하기 전에 묻습니다
- Agent view가 새 세션을 시작할 때 때때로 이전 대화를 열고 입력한 프롬프트를 삭제하는 문제를 수정했습니다
- `claude agents`: 다른 터미널에서 이미 재개한 중지된 세션을 열면 해당 대화에서 두 번째 프로세스를 시작하지 않습니다: 행이 이제 터미널에서 열려 있음을 표시합니다
- `claude agents` 및 `claude rm`이 worktree 분기가 이미 체크아웃한 기본 분기에 병합되었을 때 세션을 삭제하기를 거부하는 문제를 수정했습니다 (예: 로컬 `main`): 아직 푸시되지 않은 경우도 포함됩니다
- Background 세션이 `PermissionRequest` 또는 `PreToolUse` hook이 유효하지 않은 답변을 인쇄할 때 조용히 대기하는 문제를 수정했습니다: `claude agents` 행이 이제 hook과 schema 오류를 이름 지정합니다
- Hook이 stdout `{…}` 객체가 유효한 JSON이 아닌 경우를 조용히 일반 텍스트로 취급하는 문제를 수정했습니다: 이제 파싱 메시지가 포함된 hook 오류로 보고됩니다
- `/mcp`가 claude.ai connector 타입을 선언하는 프로젝트 `.mcp.json` 항목을 신뢰할 수 있는 "claude.ai" 제목 아래에 나열하는 문제를 수정했습니다: 이제 실제 범위 아래에 나타납니다
- `headersHelper`가 `Authorization` 헤더를 공급하는 MCP server가 401에서 OAuth 발견으로 빠지는 문제를 수정했습니다: 문서화된 대로 helper를 다시 실행하고 호출을 재시도해야 합니다
- Claude apps gateway에 대한 `/login`이 관리 설정 보안 승인 대화가 필요할 때 중단되는 문제를 수정했습니다
- Gateway model discovery (`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY`)가 `apiKeyHelper`가 유일한 자격증일 때 실행되지 않는 문제를 수정했습니다
- `claude logs`가 실행된 터미널에서 마우스 추적, bracketed paste 및 alternate screen을 켠 상태로 두는 문제를 수정했습니다
- 신뢰 대화의 저장소 권한 규칙 목록에서 긴 규칙이 emoji 중간에 잘려나갈 때 손상된 문자가 표시되는 문제를 수정했습니다
- Ctrl-C 바로 다음에 shift+tab을 누를 때 permission mode 표시자가 "Press Ctrl-C again to exit" 힌트 뒤에 숨어있는 문제를 수정했습니다
- `/ultrareview` 및 로컬에서 시드된 cloud 세션이 `prod.env` 스타일, `*.tfvars` 파일 또는 자격증 파일의 editor swap, temp, backup 사본 (예: `key.pem.tmp`, `id_rsa.swo`)에 커밋되지 않은 편집을 업로드하는 문제를 수정했습니다: 이제 머신에 남아있습니다
- CLI가 조용히 재연결한 후 Remote Control 세션이 연결된 장치에서 permission 프롬프트나 최신 메시지를 표시하지 않는 경우가 있던 문제를 수정했습니다
- Cloud 세션이 container의 세션 자격증이 아직 읽을 수 없을 때 시작 시 실패하는 경우가 있던 문제를 수정했습니다
- `claude remote-control`이 global flag 또는 wrapper-injected 옵션이 subcommand보다 앞에 올 때 자신의 플래그 (예: `--spawn`, `--name`)를 거부하는 문제를 수정했습니다
- 시작 경고 (예: "N MCP servers need authentication")가 트랜스크립트의 나머지 부분보다 한 열 오른쪽에 렌더링되는 문제를 수정했습니다
- Background worktree 세션이 checkout을 잃는 문제를 수정했습니다: background 세션이 이제 실행 중인 worktree의 lock을 보유하므로, cleanup 및 `git worktree remove`는 이를 남겨두지 않습니다
- 다른 세션의 @-멘션이 IME를 통해 입력된 비라틴 문자 이름 (예: 한국어)과 일치하지 않는 문제를 수정했습니다
- 유효하지 않은 `crossSessionInbound` 값이 조용히 무시되는 문제를 수정했습니다: 이제 경고하고 cross-session 메시지를 보유 (사용자 설정) 또는 거부 (관리 설정)하거나, 수정될 때까지 유지됩니다
- Rate-limit, usage 및 fast-mode 메시지가 해당 명령이 조직에서 사용할 수 없는 경우 `/usage-credits`를 실행하도록 알려주는 문제를 수정했습니다 (예: `DISABLE_EXTRA_USAGE_COMMAND`로 숨김)
- [VSCode] 세션이 저장되지 않았을 때 chat 탭이 "No conversation found"에 고정되는 문제를 수정했습니다: 이제 새 대화를 시작합니다
- Workflow 도구의 prompt footprint를 개선했습니다: 설명이 이제 약 1k 토큰이며 5.7k가 아닙니다: script-writing 참고는 번들된 `workflow-authoring` skill로 이동했습니다
- Prompt-footer PR 배지를 개선했습니다: pull request가 변경되지 않은 동안 GitHub를 덜 자주 확인합니다: 푸시 또는 `gh pr` 명령은 여전히 즉시 새로 고칩니다
- 관리 설정을 개선했습니다: client-side timeout, MCP startup-mode 및 stream-watchdog env vars는 더 이상 settings-approval 프롬프트를 트리거하지 않습니다
- `/ultrareview <PR#>`를 개선했습니다: Claude 계정에 연결된 GitHub 계정이 저장소에 접근할 수 있는지 시작 전에 확인하고, cloud 세션이 시작된 후 실패하는 대신 수정 방법을 설명합니다
- Cross-session messaging을 개선했습니다: 기본값을 사용할 수 없을 때 private per-user `/tmp` 디렉토리로 폴백하고, 알림 및 `/status`가 디렉토리를 이름 지정하여 수정합니다
- Agent view 디스패치 입력에서 shift+enter를 newline을 삽입하도록 변경했습니다 (프롬프트와 일치): ctrl+enter가 이제 디스패치하고 연결합니다
- `/loop`를 변경했습니다: self-paced dynamic mode와 no-prompt autonomous 기본값이 이제 Bedrock/Vertex/Foundry를 포함한 모든 경우에 사용 가능합니다
- Anthropic telemetry export 실패를 debug 레벨에서 `[Anthropic telemetry]`로 로그하도록 변경했습니다 (기존: `[3P telemetry] OTEL diag error`): OTel collector가 실패하는 것으로 착각되지 않습니다
- Linux user namespace에서 cross-session messaging을 변경했습니다: unmapped owner에 대한 root 동등 신뢰는 canonical 시스템 디렉토리로 제한됩니다
- Subagent에서 다른 세션으로의 `SendMessage`를 변경했습니다: 결과가 이제 subagent의 대화가 아닌 부모 세션의 대화로 배달되는 것을 알립니다
