> 원문: [Claude Code v2.1.305 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.305)

## 변경사항

- `sandbox.allowNestedUserNamespaces`를 추가하여 Linux의 샌드박스 명령이 사용자 네임스페이스를 생성할 수 있도록 했습니다(Chromium, rootless podman). 이를 통해 샌드박스의 파일 보호를 우회할 수 있습니다.
- `CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS`를 추가하여 무인 재시도 모드(`CLAUDE_CODE_RETRY_WATCHDOG`)가 리셋되기 전에 해제된 사용 제한을 감지할 수 있도록 했습니다.
- Vertex, Bedrock 및 기타 제공자에서 엔드포인트 또는 게이트웨이가 tool search를 거부할 때, 또는 ToolSearch가 비활성화되거나 `--tools`에서 제외된 게이트웨이 뒤에 있을 때 모든 요청이 실패하는 문제를 수정했습니다(2.1.304 regression). Claude Code는 이제 이를 제외하고 재시도합니다.
- 모델 이름이 `modelOverrides` 값과 대문자 또는 `[1m]` 태그로 다를 때 `/effort` 및 `/autocompact` 설정이 적용되지 않는 문제를 수정했습니다.
- bare 저장소의 새 worktree가 때때로 기본 분기 대신 로컬 HEAD에서 시작되는 문제, 그리고 변경되지 않은 subagent worktree가 정리되지 않는 경우가 있는 문제를 수정했습니다.
- 디스크가 가득 찬 경우 Bash 명령이 원본 `ENOSPC` 파일 경로로 실패하는 문제를 수정했습니다. 이제 디스크가 가득 찼으며 아무것도 실행되지 않았다고 표시합니다.
- 클라우드 세션이나 SDK의 `setMcpServers`로 전달된 MCP server가 나중에 세션에서 자신의 설정의 같은 이름 server로 대체되는 문제를 수정했습니다.
- subagent가 fallback model로 전환한 후 Claude가 subagent 작업의 잘못된 모델을 명명하는 문제를 수정했습니다.
- 클라우드 세션 및 팀 멤버가 compaction이 요약에 가장 오래된 메시지를 제외해야 했을 때 Claude에게 알리지 않는 문제를 수정했습니다.
- 예약된 Cowork 클라우드 세션이 URL 승인이 필요한 각 subagent의 WebFetch에 대해 5분을 기다리는 더 많은 경우를 수정했습니다.
- Workflow resume이 실행 저널에서 이미 완료된 `pipeline()` 및 `parallel()` agent를 다시 실행하지 않고 제공하는 문제를 수정했습니다.
- Remote Control이 `/resume`으로 대화를 전환한 후 `/resume`에 빈 "(session)" 항목을 남기는 문제를 수정했습니다.
- `/usage` 행이 좁은 터미널에서 잘리는 문제를 수정했습니다.
- 시작 경고가 로고 위에 원본 텍스트로 출력되는 문제를 수정했습니다. 이제 debug log로 전송되며, 아무것도 제한하지 않는 권한 규칙은 배너 아래의 경고 행으로 표시됩니다.
- 화면 판독기 모드를 수정했습니다. 검색 상자는 이제 VoiceOver가 "telephone recorder"로 읽는 기호 대신 "Search:"라고 표시하며, Ctrl+R 검색 결과 및 "ultrathink"와 같은 강조 표시된 프롬프트 텍스트는 더 이상 단어 내에 공백이 없습니다.
- Self-hosted runner: stdout만 runner 또는 orchestrator와 공유하는 start 스크립트가 `TERM`이 설정되었을 때 `Resource temporarily unavailable`로 실패하는 문제를 수정했습니다(2.1.300 regression).
- Self-hosted runner: git credential helper 또는 askpass 프로그램이 `GIT_CONFIG`를 통해 설정을 읽을 때 2.1.296 이후 저장소 접근이 실패하는 문제를 수정했습니다.
- Self-hosted runner: orchestrator가 시작된 runner가 출력을 열어둔 상태로 유지될 때 spawn-runner hook이 시간 초과되었다고 보고하는 문제를 수정했습니다.
- `/usage`를 개선했습니다. 각 경고는 이제 출처를 명시하는 한 줄 수정이며, `f`는 수정 사항을 적용합니다. 같은 수정 사항이 VS Code 및 `/doctor`에 나타납니다.
- MCP 동의 대화를 개선하여 프롬프트용 Enter가 Accept로 인식될 가능성이 낮아졌습니다.
- mod의 `Image`를 개선하여 iTerm2 3.5 이상에서 fullscreen rendering으로 그림을 그리도록 했습니다. 여기서는 `alt` 텍스트만 표시되었습니다.
- Remote Control: spawn-mode 메시지를 개선했습니다. `w`를 누르면 이제 새 모드가 폴더에 저장된다고 표시되며, 저장된 모드를 사용하는 나중의 `claude remote-control` start는 어디서 왔는지 표시합니다.
- `allowedMcpServers`를 변경하여 `env`에서만 `${VAR}`을 사용하는 `managed-mcp.json` stdio server 필터링을 중지했습니다. allowlist에서 제외된 서버는 이제 업그레이드 시 로드됩니다. `deniedMcpServers`를 사용하여 비활성 상태로 유지할 수 있습니다.
- Claude Desktop이 경로로 마운트하는 plugin이 조직의 관리 설정이 `allowManagedPermissionRulesOnly`를 설정할 때 더 이상 `allowed-tools`를 유지하지 않도록 변경했습니다.
- `/artifacts` 삭제 확인을 변경하여 1 또는 Enter를 누르면 유지, 2를 누르면 삭제, Esc를 누르면 취소합니다. `y` 및 `n`은 더 이상 답변하지 않습니다.
- mod의 docked pane을 터미널 너비의 45% 이내로 유지하도록 변경했습니다. 더 넓은 터미널에서 유지된 너비도 포함합니다.
- [VSCode] SessionStart 또는 Setup hook이 실행되는 동안 "Running start-up hooks" spinner 상태 및 화면 판독기 공지를 추가했습니다.
- [VSCode] `spinnerVerbs` 설정이 기본 제공 동사를 짧은 동사로 대체할 때 spinner가 "Compacting..."을 자르는 문제를 수정했습니다.
- [VSCode] 세션이 시간 내에 시작되지 않고 hook이 실행 중이지 않을 때 표시되는 메시지를 변경했습니다. 이제 출력 로그를 먼저 표시하고 원인을 나열하며 로그인 및 네트워크를 먼저 가리키지 않습니다.
- [Cloud sessions] Cloud environments 관리 페이지가 기존 환경을 "installs packages" 오류로 저장하지 못하는 문제를 수정했습니다.
- [Cloud sessions] self-hosted 환경 삭제를 개선하여 대화와 오류 메시지가 삭제를 차단하는 것과 영향을 받을 것을 표시합니다.
- [Claude Tag] Claude가 아직 참여하지 않은 공개 Slack 채널을 Claude Tag 관리자 추가 위치 검색에 추가했으므로 관리자가 여기서 설정할 수 있습니다.
- [Claude Tag] Claude Tag 액세스 번들이 다른 GitHub 계정으로 이동한 저장소를 다시 추가할 수 있도록 수정했습니다.
- [Claude Tag] Slack DM 스레드에서 설정된 routine이 해당 스레드의 다른 routine이 대화를 다시 시작한 후 더 이상 게시되지 않는 문제를 수정했습니다. 이제 둘 다 계속 게시됩니다.
- [Claude Tag] 대화가 끝난 후 Slack 스레드에서 설정된 routine이 게시하지 않고 성공을 보고하는 문제를 수정했습니다. 이제 이러한 실행은 건너뛰고 작성자에게 알립니다.
- [Claude Tag] 대규모 조직의 Claude Tag 관리자 페이지를 개선하여 채널 목록이 아직 로드 중일 때도 plugin, skill 및 bundle 편집이 작동합니다.
- [Code Review] Code Review가 review 중에 여러 push가 pull request에 도착했을 때 최신 커밋을 검토하지 않는 경우가 있는 문제를 수정했습니다.
- [Code Review] Code Review re-review를 변경하여 이전 blocking findings이 아직 열려 있는 동안 LGTM으로 열지 않습니다.
