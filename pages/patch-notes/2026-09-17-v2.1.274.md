> 원문: [Claude Code v2.1.274 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)

## 변경사항

- 메모리 사용량이 위험 수준일 때 메모리를 확보하거나 안전하게 재시작하는 단계를 포함한 시각적 경고를 추가했습니다
- 첫 번째 비대화형 턴이 MCP 서버 연결을 기다리는 시간을 제한하는 `CLAUDE_CODE_MCP_STARTUP_WAIT_MS`를 추가했습니다(`0` = 대기하지 않음)
- `claude_code.llm_request` OpenTelemetry trace span에 `effort` 속성을 추가했으며, `api_request` 이벤트와 일치합니다
- `claude_code.managed_settings_resolved` OTel 이벤트를 추가했습니다: managed-settings 소스 및 정책 helper 상태, `OTEL_LOG_MANAGED_SETTINGS=1`로 설정 및 다이제스트를 편집합니다
- Claude apps gateway 구성에 `store.connect_timeout_seconds`를 추가하여 Postgres 연결 시간 초과를 연장했으며(기본값 5초), 데이터베이스를 사용할 수 없을 때 부팅 오류를 개선하여 `store.postgres_url` 및 구성된 시간 초과를 가리킵니다
- `enduser.sub`(IdP 주제)를 Claude Desktop 및 Cowork가 Claude apps gateway를 통해 전송하는 원격 분석에 추가했습니다
- 레플리카가 한 번에 업스트림으로 전송하는 256개보다 많은 열린 요청을 가질 때 Claude apps gateway 경고를 추가했으며, 그 한계를 보여주는 시작 로그 라인을 추가했습니다
- 전체 화면 모드에서 축소된 팀원 및 에이전트 메시지를 클릭하여 펼칠 수 있는 기능을 추가했습니다
- 세션이 "예기치 않은 tool_use_id" 400 오류를 무한 재시도하는 상황을 수정했습니다: 손상된 트랜스크립트가 가능한 경우 자동 복구되며, 그렇지 않으면 명확한 오류(`/rewind` 힌트 포함)가 루프를 끝냅니다
- `http`로 구성되고 레거시 HTTP+SSE만 지원하는 MCP 서버가 첫 요청에 422 또는 다른 4xx 오류로 응답할 때 연결 실패 문제를 수정했습니다
- Streamable HTTP MCP 도구 호출이 더 긴 서버별 `timeout`이 설정되어 있어도 약 5분 후 시간 초과되는 문제를 수정했습니다
- `listChanged`를 선언하지 않고 list-changed 알림을 보낼 때 MCP 프롬프트 및 리소스가 새로 고쳐지지 않는 문제를 수정했습니다
- 403 insufficient_scope로 거부된 MCP 도구 호출이 만료된 로그인으로 보고되는 문제를 수정했습니다: 이제 오류가 누락된 권한을 명시하고 `/mcp` 재인증을 가리킵니다
- 반응형 압축 후 컨텍스트가 다시 오버플로우될 때 hook 기반 세션(활성 `/goal`과 같은)이 압축 대신 "프롬프트가 너무 깁니다"로 끝나는 문제를 수정했습니다
- 세션을 재개(`--continue` / `--resume`)할 때 활성 `/goal`이 손실되는 문제를 수정했습니다
- `claude agents`가 자동 업데이트 재시작 후 `--model`, `--effort`, `--permission-mode`, `--allow-dangerously-skip-permissions` 및 `--agent`를 잃는 문제를 수정했습니다
- 언어 서버가 수천 개의 파일에 대해 프로젝트 전체 진단을 게시할 때 턴별 속도 저하 문제를 수정했습니다
- Bedrock, Vertex 또는 Foundry의 `model: "opus"`를 가진 subagent가 `ANTHROPIC_DEFAULT_OPUS_MODEL`이 설정되지 않은 경우 인식할 수 있는 모델 family가 없는 ID일 때 세션의 모델을 떠나는 문제를 수정했습니다
- 자체 호스팅 runner 세션이 몇 번의 실패한 토큰 새로 고침 후 다음 예약된 새로 고침까지 모든 턴에서 401로 실패하는 문제를 수정했습니다. runner는 이제 재시도를 계속하며 401 후 새 토큰을 가져옵니다
- 클릭 가능한 로컬 파일 경로 링크가 VS Code 및 `file://` URI가 필요한 다른 터미널에서 아무것도 하지 않는 문제를 수정했습니다
- 트랜스크립트가 자체 메시지의 순서 있는 목록을 다시 번호 매기는 문제를 수정했습니다("3. 2. 1."이 "3. 4. 5."로 표시됨), 이제 숫자 및 "N)" 마커가 입력한 대로 표시됩니다
- AskUserQuestion 미리보기 노트가 강조된 옵션 대신 이전에 선택한 옵션에 첨부되는 문제를 수정했습니다
- AskUserQuestion 미리보기 모드가 Enter로 노트를 제출할 때 강조된 옵션을 삭제하는 문제를 수정했습니다
- 재개된 background 에이전트가 메시지로 승인된 호출 중 하나일 때 중단된 도구 배치의 절반을 유지하는 문제를 수정했습니다
- `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`으로 시작한 로컬 `claude -p --resume`이 이전 프로세스가 남긴 미완료 background 작업을 보고하지 않는 문제를 수정했습니다
- 아직 연결 중인 SDK 호스팅 MCP 서버의 도구 없이 클라우드 세션의 첫 번째 턴이 시작되는 경우가 있는 문제를 수정했습니다
- background 에이전트가 자체 background 작업을 기다리고 있고 재개될 예정일 때 background 에이전트 알림이 에이전트에 live background 작업이 없다고 주장하는 문제를 수정했습니다
- Claude Desktop 세션의 오류 힌트가 CLI 플래그 대신 `/usage-credits`와 같은 슬래시 명령을 제안하도록 수정했습니다
- `/schedule`이 routine의 프롬프트를 저장할 때 message role 없이 저장하는 문제를 수정했습니다
- `/status`가 자체 오류 배너가 확인하도록 말한 `apiKeyHelper` 실패를 표시하지 않는 문제를 수정했습니다
- 비대화형 세션에서 `/fast on`이 조직의 managed fast mode 정책 하에서 켜지고 꺼지는 것을 보고하는 문제를 수정했습니다. 이제 조직이 비활성화했다고 표시합니다
- Artifact 도구가 업데이트 승인을 요청했지만 세션이 최신 버전을 읽지 못해 거부하는 문제를 수정했습니다
- Cowork 및 claude.ai 클라우드 세션이 네트워크 액세스를 켠 상태에서 팀원의 artifact 읽기를 마치 네트워크 액세스가 꺼진 것처럼 처리하는 문제를 수정했습니다
- 자체 git 리포지토리가 없는 플러그인 또는 마켓플레이스 디렉토리가 git 관리 `~/.claude`와 같은 둘러싼 git 리포지토리에서 버전을 가져오는 문제를 수정했습니다
- 빈 `--mcp-config`를 사용한 `--strict-mcp-config`가 우발적인 MCP 서버에 대해 최대 `MCP_TIMEOUT`까지 첫 번째 비대화형 턴을 유지하는 문제를 수정했습니다
- Stop 프롬프트 hook이 대화의 모든 블록에서 전체 프롬프트를 다시 보내는 문제를 수정했습니다. 반복 블록은 이제 500자 레이블로 조건을 명시합니다
- Linux의 Wayland에서 Cursor 또는 VS Code 터미널 내에서 실행할 때 시작 시 추가 빈 편집기 창이 열리는 문제를 수정했습니다
- Postgres가 지출 확인 중에 연결을 끊을 때 Claude apps gateway에서 처리되지 않은 promise 거부 문제를 수정했습니다
- Claude apps gateway가 SIGTERM에서 모든 열린 스트림을 자르는 문제를 수정했습니다: 종료하기 전에 최대 25초 동안 진행 중인 요청이 완료되도록 합니다(`CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS`)
- 플러그인 정책이 remote managed settings에서 올 때 `installed_plugins.json`이 거의 매 시작마다 다시 작성되는 문제를 수정했으며, 이는 Claude Desktop이 모든 열린 세션의 플러그인을 다시 로드하게 했습니다
- headless 및 SDK 세션이 완료된 모든 background 작업에 대해 별도의 모델 호출을 하는 문제를 수정했습니다. 이미 대기열에 있는 완료는 이제 한 호출로 응답됩니다
- Bash 도구가 모든 플러그인 새로 고침 후 shell 프로필을 다시 소싱하는 문제를 수정했습니다(다음 명령에 대한 몇 초 지연). 이제 플러그인의 `bin/` 디렉토리가 변경되었을 때만 그렇게 합니다
- `hooks/hooks.json`에서 top-level `$schema`를 가진 플러그인이 "unknown key" 공지를 표시하는 문제를 수정했습니다
- MCP 연결 오류 및 MCP 로그인 도구의 설명이 MCP 구성에서 `${VAR}` 플레이스홀더에서 확인된 secret을 표시하는 문제를 수정했습니다
- 특정 특수 shell 변수를 루핑하거나 할당하는 명령에 대한 Bash 권한 확인 문제를 수정했습니다. 이러한 명령은 이제 권한을 요청합니다
- worktree 격리 세션이 특정 중첩 shell 확장을 사용하는 Bash 명령을 수락하는 문제를 수정했습니다. 이들은 이제 거부됩니다
- Edit 권한 프롬프트 미리보기가 다중 바이트 문자가 있는 파일에서 승인된 edit과 다른 위치를 표시하는 경우가 있는 문제를 수정했습니다
- background 명령이 mild 메모리 압박 상태의 머신에서 30분 유휴 후 중지되는 문제를 수정했습니다. 이제 메모리가 매우 부족할 때만 중지되며, 디버그 로그가 이유를 표시합니다
- subagent가 main 세션으로 보낸 메시지가 재시작 후 Claude Desktop 트랜스크립트에서 사라지는 문제를 수정했습니다
- `.zip`에서 로드된 플러그인이 여러 겹치는 재로드 후 오래된 추출에서 제공되는 문제를 수정했습니다
- sub-agent의 진행 상황 요약이 runaway multi-paragraph 회신으로 대체되는 문제를 수정했습니다
- `--input-format stream-json` 세션에서 시작을 개선했습니다: 첫 번째 턴이 더 이상 아직 연결 중인 MCP 서버(tool search가 지연)의 도구를 기다리지 않으며, 그들은 나중 턴에 도착합니다
- Monitor 도구 알림을 개선했습니다: 스크립트의 최종 출력 및 종료가 두 개의 알림 대신 하나의 알림으로 도착하여 모델 턴을 절약합니다
- Artifact 도구 오류를 개선했습니다: claude.ai에 로그인하지 않으면 터미널은 첫 시도에서 그렇게 말하며, Claude는 거부된 호출을 더 빨리 다시 시도하지 않도록 지시됩니다
- artifact 발행
